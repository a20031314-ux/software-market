# 모듈앱 마켓 — main

> 이 문서는 "앱 판매(마켓·크몽·숨고)" 프로젝트의 모든 채팅이 공유하는 기준 문서예요.
> **새 채팅을 시작하면 먼저 이 문서를 읽고**, 작업이 끝나면 아래 "현재 상태"와 "작업 기록"을 갱신해 주세요.
> 마지막 갱신: 2026-11-14

## 1. 한 줄 요약
이미 만든 앱(동호회·회원 연결·운동·AI 언어 학습)과 기능 모듈을 **템플릿으로 조합해 팔고**, 설치·배포까지 대행하는 사업. 이 저장소는 그 소개·문의 사이트(**모듈앱 마켓**, https://apps.languagebank.net). 판매 창구는 크몽·숨고 + 이 사이트.

## 2. 사용자와 원칙
- 사용자: 1인 개발. 기능 모듈을 많이 만들어 둠(영어앱·동호회 앱·운동 앱·소싱봇 등). 운영 부담 없이 **팔아서 넘기는** 방식 선호.
- **컨설팅은 하지 않는다.** "이런 문제가 있다" → "이 기능을 붙여 드린다 + 가격"으로만 답한다. 상담 대신 **질문지 1장**.
- **납품형이 기본**: 구매자 명의(Vercel·Upstash·스토어 계정)로 배포, 소스 전달. 서버비·스토어비·PG·AI 사용료는 구매자 몫. 구독형(내 서버에 가게 하나)은 옵션.
- **비독점 템플릿**: 같은 템플릿을 여러 구매자에게 판다. 구매자 전용 기능은 구매자 소유, 템플릿 재판매 금지. 독점은 별도 가격(지역 ×2~3, 기간 ×3~5).
- 차이는 **템플릿·설정으로만** 둔다(구매자마다 코드를 갈라치지 않음). 맞춤 기능도 가능하면 공용 코어의 끄고 켜는 모듈로 → 다음 구매자에게 옵션으로 또 판다.
- 디자인은 템플릿 기준, 이름·색·문구·로고만 바꿈. 화면 배치 새 디자인은 포함 안 함.
- 화면·문구에 앱 이름·가격을 박아 두지 말고 한 곳(`index.html`의 `PRODUCTS`)에서 고친다.

## 5. 판매 창구 현황
### 크몽
- 프로필: 소개글 **255자 제한·제한 단어 있음**('소개팅·매칭' 의심, 외부 링크도 막힐 수 있음). 사용 중인 소개글은 "앱 제작을 합니다. 로그인, 회원 관리, 채팅, 게시판, 결제, 관리자 화면 같은 기능을 이미 모듈로 만들어 두었습니다…"(243자).
- 서비스 1호: **"앱 제작 - 이미 만든 모듈 조합으로 빠르고 저렴하게"**, IT·프로그래밍 > 앱. 패키지 STANDARD 웹앱 기본형 90만/7일/수정1 · DELUXE 웹앱+결제 190만/14일/수정2 · PREMIUM 스토어 출시형 390만/30일/수정3. 추가 옵션(빠른 작업 +50%, 추가 수정 10만, 페이지 15만, 기능 30만~, 결제 30만, 광고 20만, 기획서 20만, 본인인증 20만, 추가 기능 1개 30만, 유지보수 월 20만). 검색 키워드: 앱 제작·커뮤니티 앱·동호회 앱·MVP 개발·운동 앱 개발.
- 심사 주의: "별도 견적/협의" 표현 금지 → 금액이 보이게. 경력("Play 출시·운영 중")은 증빙 필요(전문가 프로필에 Play 화면 캡처). '최고·유일·100% A/S' 금지. 크몽에서 만난 구매자를 이 사이트로 데려가 직거래하면 규정 위반 → 크몽 메시지에 사이트 주소 보내지 않기.

- 커머스 모듈(상품·옵션·재고·장바구니·주문·포트원 결제·배송 상태·판매자 화면)을 `dating` 공용 코어에 끄고 켜는 모듈로 — 3~4주 추정. 이어서 회원 간 거래, 다국어·번역 채팅(영어앱에서 옮김)
0. 헬스장 업종 실제 동작 데모(기본 + 혼잡도 + 회원권·출석 QR) — `dating` 공용 엔진에 업종 모듈 추가, 1~2주 추정. 나머지 업종은 문의 오는 순서로
1. 크몽 서비스 제출 마무리 → 심사 반려 시 사유 반영
2. 사이트 이름 확정 → `index.html`·`admin.html` 제목·로고 교체
3. 새 문의 알림(이메일 또는 카카오톡)
4. 네이버 서치어드바이저·구글 서치 콘솔 등록 — 사이트 쪽 준비 끝(robots.txt·sitemap.xml·og 태그·og.jpg, PR #2). 남은 것: 사용자가 두 곳에 사이트 등록 → 확인 태그 값 받아 `index.html` 주석 자리에 넣기 → 사이트맵 제출
5. 템플릿에 사업자 정보·이용약관·환불 정책 화면(카드사 심사용) — `dating` 저장소
6. 회비·참가비 결제, 회원 구독(동호회·멤버십 상품)
7. 영상통화·인앱결제를 코어로(회원 연결 상품 상위 패키지)
8. 선생님 화면·학생 기록 서버 저장(학원·한국어 학습 앱)
9. 구매자 준비 안내서·운영 설명서·질문지 양식, 구매자별 납품본 만드는 스크립트
10. 사업자 등록(세금계산서·PG·기업 판매에 필요). 집 주소 노출이 싫으면 비상주 사무실 검토 → 그 뒤 네이버 플레이스 검토

## 8. 결정 기록
- **판매 방식(11/13)**: 납품형 기본, 구독형 옵션. 질문지로 진행, 컨셉·콘텐츠·로고는 구매자 몫.
- **결제(PG)(11/13)**: 신청~실결제 약 3주. 테스트 결제로 먼저 납품 → 심사 통과 후 실결제 키 전환 1회 포함.
- **단체채팅·보이스룸(11/13)**: 동호회 전체 단체방은 스탠다드 이상 기본, 방 나누기 등은 옵션 30~80만. 보이스룸은 온라인 모임용 옵션 150~300만 + 음성 서버 사용료 구매자 부담, 녹음 기본 제외.
- **기업용(11/14)**: 1순위 다지점 회원 앱(지금 가게 구조 그대로). 먼저 사업자 등록·세금계산서·표준 계약서·유지보수 약속. 크몽·숨고 사례 → 작은 기업 패키지 → 위시켓·직접 영업.
- **Languagebank 언어별(11/14)**: 내 서비스는 앱 하나로 유지(같은 앱 여러 개 = 구글 반복 콘텐츠·애플 4.3 위험). 판매용만 "○○어 학습 앱"으로, 1순위 한국어 학습 앱(어학당·유학생 학원). 확인: 언어별 레벨 측정 단어 원어민 검토, 띄어쓰기 없는 언어(태국어 등) 문장 분석, AI 사용료 구매자 키.
- **네이버 플레이스(11/14)**: 자택 주소가 지도에 공개되고 방문형 서비스용이라 보류. 대신 사이트 + 검색 등록 + 블로그.
- **PG(11/14)**: 지금은 신청 안 함. 크몽·숨고는 플랫폼이 결제, 구매자 앱 결제는 구매자 명의 PG. 판매자 PG는 시스템 서비스 월 구독을 실제로 받거나 사이트에서 카드 결제를 받을 때 → 순서: 사업자 등록 → 통신판매업 신고 → 사이트에 사업자 정보·약관·환불 정책 → 포트원 PG(약 3주).
- **시스템 서비스 분리(11/14)**: 사이트를 앱 판매(납품형)와 시스템 서비스(자영업용, 월 구독 중심)로 나눔.
- **아이디어 사업자 고객층(11/14)**: "팔 것이 있고 사용자끼리 이어져야 하는데 개발이 필요한 사업자"(한일 매칭, K팝 굿즈 팬 마켓, 산책 메이트, 언어 교환, 클래스 마켓 등)를 앱 판매의 주 고객으로. 데이팅에 한정하지 않음. 업종별 신고·등록(결혼중개업법, 일본 인터넷이성소개사업 신고, 통신판매중개, 굿즈 초상권·상표)은 단정하지 않고 확인할 곳 안내.
- **분야별 전문 기능(11/14)**: 사용자 관리만이 아니라 분야 기능(학습 워크스페이스·학습 데이터 등)이 필요한 사업자용으로 기능 묶음을 보여 줌. 없는 것은 ○ 준비 중으로 정직하게 표시하고, 문의가 오면 공용 코어 모듈로 만들어 다음 구매자에게 재사용.
- **학원 학습 진단 가격(11/15 확정)**: 월 구독 기본 — 라이트 69,000 / 스탠다드 129,000 / 프로 229,000원(학생 30/80/200명, 초과 1명 1,500원, 연간 2개월 무료). 옵션: 자체 도메인 10만, 스토어 앱 70만, 상권 독점 +50%, 기존 데이터 이전 30~80만, AI 말하기 월 +3만 + 사용량. 설치형 390만~ + 유지보수 월 15만~. 대형 학원 연 라이선스 300~1,500만, 체인 구축 1,500~3,000만 + 지점별 연 200~400만, 유료 시범 운영(4주) 200~500만. 첫 고객 3개월 무료 → 6개월 50%(서면). 학원에는 "관리 옵션 추가 징수" 대신 관리형반 교습비 등록을 안내. 웹앱 기본(학생은 링크·코드로, 설치 없음), 스토어 앱은 옵션. 학원 브랜드(이름·로고·색) 기본 포함. 자세한 것은 프로젝트 문서 `학원_학습진단_모듈_구상.md`.
- **조직 키트 포지셔닝(11/14, 수정)**: 경쟁 제품이 있다고 피하지 않는다. 기존 프로그램은 "모든 조직에 같은 기능", 우리는 "기본 운영 + 그 조직만의 전용 모듈"(대회·체력 측정·성장 프로필·레벨 테스트·상황 요청·재실·내부 안내 등). 경쟁이 있는 시장 = 수요 확인된 곳. 학원 보류 결정 취소. 우선순위 기준은 '공백'이 아니라 '조직마다 다른 일이 많은가 + 전용 모듈 재사용성'. 표는 프로젝트 문서 `조직_우선순위_조사.md`.
- **사이트(11/14)**: 소프트웨어 마켓 형태, 문의는 사이트 안 문의창 → Upstash 저장 → 문의함. 영어앱 도메인의 서브도메인 `apps.`에 연결(영어앱과 분리, 실제 운영 앱이라는 신뢰). 커지면 전용 도메인으로 이전.

## 10. 채팅 규칙
- 이 문서 = 기준. 결정이 바뀌면 여기부터 고친다.
- 각 채팅은 끝날 때 5·6·7·9번을 갱신한다.
- 답·커밋 메시지·주석은 한국어로. API 키·비밀번호는 채팅·코드에 넣지 않는다(사용자가 Vercel에 직접).
- 돈이 나가는 일·되돌리기 어려운 일(배포 주소 변경, 데이터 삭제)은 확인 받고 한다. 법·세금은 단정하지 않고 확인할 곳을 짚는다.
