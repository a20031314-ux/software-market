# 모듈앱 마켓 — main

> 이 문서는 "앱 판매(마켓·크몽·숨고)" 프로젝트의 모든 채팅이 공유하는 기준 문서예요.
> **새 채팅을 시작하면 먼저 이 문서를 읽고**, 작업이 끝나면 아래 "현재 상태"와 "작업 기록"을 갱신해 주세요.
> 마지막 갱신: 2026-11-15

## 1. 한 줄 요약
이미 만든 앱(동호회·회원 연결·운동·AI 언어 학습)과 기능 모듈을 **템플릿으로 조합해 팔고**, 설치·배포까지 대행하는 사업. 이 저장소는 그 소개·문의 사이트(**모듈앱 마켓**, https://apps.languagebank.net). 판매 창구는 크몽·숨고 + 이 사이트.

## 2. 사용자와 원칙
- 사용자: 1인 개발. 기능 모듈을 많이 만들어 둠(영어앱·동호회 앱·운동 앱·소싱봇 등). 운영 부담 없이 **팔아서 넘기는** 방식 선호.
- **컨설팅은 하지 않는다.** "이런 문제가 있다" → "이 기능을 붙여 드린다 + 가격"으로만 답한다. 상담 대신 **질문지 1장**.
- **납품형이 기본**: 구매자 명의(Vercel·Upstash·스토어 계정)로 배포, 소스 전달. 서버비·스토어비·PG·AI 사용료는 구매자 몫. 구독형(내 서버에 가게 하나)은 옵션.
- **비독점 템플릿**: 같은 템플릿을 여러 구매자에게 판다. 구매자 전용 기능은 구매자 소유, 템플릿 재판매 금지. 독점은 별도 가격(지역 ×2~3, 기간 ×3~5).
- 차이는 **템플릿·설정으로만** 둔다(구매자마다 코드를 갈라치지 않음). 맞춤 기능도 가능하면 공용 코어의 끄고 켜는 모듈로 → 다음 구매자에게 옵션으로 또 판다.
- 디자인은 템플릿 기준, 이름·색·문구·로고만 바꿈. 화면 배치 새 디자인은 포함 안 함.
- 화면·문구에 앱 이름·가격을 박아 두지 말고 한 곳(`index.html`의 `PRODUCTS`)에서 고친다.

## 8. 결정 기록
- **확장 1단계 = 기능 모듈부터(11/15)**: 업종을 늘리기 전에 모든 업종에 걸리는 빈칸(알림 / 이용권·예약·출석 / 역할·권한 / 회원 결제)을 공용 코어 모듈로 먼저 채운다. 순서 1순위(알림 → 예약·출석 → 역할 → 회원 결제) → 2순위(공개 소개·체험·가져오기, 기록 엔진은 #14로 됨) → 3순위는 문의 시. 웹 푸시는 기본 포함, 알림톡·문자는 옵션(발송비 구매자 부담). 예약 모듈 규칙: 예약 때 1회 차감, 취소 마감 전 취소만 돌려줌, 노쇼 그대로, 대기는 차감 없이 자리가 나면 자동 예약, QR 출석은 하루 한 번, 결제는 모듈 밖(관리자 발급 → ③에서 결제 연동).
- **업종 장면 페이지 공통(11/15, 동호회에서 정함)**: 아직 없는 모듈도 페이지에 넣되 화면 없이 "준비 중" + 흐름 3줄로(가짜 화면을 만들지 않음). 장면용 가상 데이터는 배포 체험(`demo-seed.py`)과 분리한 **로컬 전용 시드**(`scripts/<업종>-demo-seed.py`), 글·채팅 시각은 캡처용 서버 시계 옮기기(`demo-clock.cjs`)로 분산. 없는 기능(예: 게시판 댓글)은 캡션에도 쓰지 않음.
- **모듈 소개 방식(11/15)**: 방문자가 직접 세팅하는 체험 대신, 모듈마다 기본 데모 버전을 만들고 가상 데이터로 찍은 **장면 스크린샷 3~4컷**(누가 → 무엇을 → 이렇게 된다)으로 보여 준다. 업종 페이지는 **추천 모듈부터**(학원: 진단·리포트 → 맞춤 시험지 → 풀이·힌트), 그다음 다음 단계·기본 포함. 직접 눌러 보는 샘플은 보조로만. 질문·피드백 모듈은 스탠다드로 표시(가격 미확정).
- **홈 화면 설치(11/15)**: 웹앱은 스토어 없이 링크로 설치. 조직이 네이버 플레이스·카톡 채널·매장 QR에 거는 주소는 앱 주소가 아니라 **설치 안내 `/install?t=<가게>`**(네이버·카톡 안 브라우저는 홈 화면 설치가 안 되거나 안 보여서 바깥 브라우저로 넘김). 가게별 이름·아이콘(가게 관리자가 올림, 없으면 가게 색 기본 아이콘). 기본 패키지에 포함. 네이버 플레이스 등록은 조직이 직접(받는 링크는 스마트플레이스 도움말 확인). 서브도메인(`가게.도메인`)도 코드상 지원 — DNS는 사용자가.
- **업종별 공통 구조·질문지(11/15)**: 모든 업종을 같은 뼈대로 본다 — 조직·지점 / 그룹(반·클래스·모임) / 사람·역할 / 일정 / 기록 / 돈 / 알림. 업종마다 이름표만 다름. 질문지는 ① 공통 체크(지점 수·규모·역할·결제) ② 업종 체크(학원: 수업 대상·과목·분반 기준·수업 형태·관리 항목) ③ 서술(지금 쓰는 도구·불편한 일·우리만의 방식·핵심 가치). **체크 = 설정만으로 바로 되는 것(데모 자동 생성), 서술 = 견적이 필요한 것(전용 모듈).** 아직 없는 기능은 체크 항목에 넣지 않거나 ○ 준비 중 표시.
- **판매 흐름(11/15)**: 문의(업종별 질문지) → 체크값으로 데모 가게 자동 생성 + 샘플 데이터 → 7일 체험 → 조율(설정으로 되는 것은 기본 가격, 새로 만들 것은 전용 모듈 견적 → 다음 구매자 옵션으로 재사용) → 납품형/구독형 판매.
- **만드는 방식(11/15)**: 업종별로 따로 만들지 않고, 처음부터 전부 만들지도 않는다. **구조(틀)는 하나, 내용은 업종별 데이터 파일, 출시는 하나씩**. 공용: 질문지 화면·설정 변환·데모 생성. 업종별: `club`·`gym`·`academy` 데이터 파일(체크 항목·이름표·기본 모듈 묶음·샘플 데이터). 출시 순서 동호회(데모 있음, 흐름 검증) → 헬스장 → 학원(학습 모듈 진행에 맞춰).
- **공개 소개·홍보(11/15)**: 기본 패키지의 가게 소개를 로그인 없는 공개 소개 화면으로(핵심 가치·구조·가격·강사·위치·문의). 운영 앱과 같은 데이터 → 자동 반영 + 체험 신청이 회원으로 바로 이어지는 것이 일반 홈페이지 도구와의 차이. **문구·컨셉 작성은 안 함**(구매자 몫, 핵심 가치는 질문지 서술 항목으로 받아 그대로 넣음). 네이버 스마트플레이스 홈페이지 칸에 거는 용도 — 받는 링크 종류는 스마트플레이스 도움말에서 확인, 등록은 구매자가 직접. 학원 가격 공개는 교습비 게시 관련 규정을 관할 교육청에 확인하도록 안내.
- **체험 기능(11/15)**: 고가 옵션으로 판다(근거: 체험 → 결과 → 상담 → 등록 전환). 공통 엔진 = 게스트 계정 + 기간 제한 + 정회원 전환. 체험 기본 50만, 업종별 체험 고급 150~250만(추정, 설치형 기준). 학원은 레벨 테스트 + 자동 진단 리포트 + 학생 화면 맛보기 + 체험 수업 예약(`/demo/academy`·학습 모듈 재사용), 헬스장 1회 체험권·QR, 동호회 게스트 정모 참가. 실시간 체험 수업(영상통화)은 문의, 처음엔 비추천. 미성년자 체험은 보호자 명의 신청(만 14세 미만 동의 요건은 개인정보보호위원회 안내 확인). "실력 향상 보장"류 표현 금지.
- **판매 방식(11/13)**: 납품형 기본, 구독형 옵션. 질문지로 진행, 컨셉·콘텐츠·로고는 구매자 몫.
- **결제(PG)(11/13)**: 신청~실결제 약 3주. 테스트 결제로 먼저 납품 → 심사 통과 후 실결제 키 전환 1회 포함.
- **단체채팅·보이스룸(11/13)**: 동호회 전체 단체방은 스탠다드 이상 기본, 방 나누기 등은 옵션 30~80만. 보이스룸은 온라인 모임용 옵션 150~300만 + 음성 서버 사용료 구매자 부담, 녹음 기본 제외.
- **기업용(11/14)**: 1순위 다지점 회원 앱(지금 가게 구조 그대로). 먼저 사업자 등록·세금계산서·표준 계약서·유지보수 약속. 크몽·숨고 사례 → 작은 기업 패키지 → 위시켓·직접 영업.
- **Languagebank 언어별(11/14)**: 내 서비스는 앱 하나로 유지(같은 앱 여러 개 = 구글 반복 콘텐츠·애플 4.3 위험). 판매용만 "○○어 학습 앱"으로, 1순위 한국어 학습 앱(어학당·유학생 학원). 확인: 언어별 레벨 측정 단어 원어민 검토, 띄어쓰기 없는 언어(태국어 등) 문장 분석, AI 사용료 구매자 키.
- **네이버 플레이스(11/14)**: 자택 주소가 지도에 공개되고 방문형 서비스용이라 보류. 대신 사이트 + 검색 등록 + 블로그. (11/15: 이것은 **내 사업**의 플레이스 등록 얘기. 구매자 가게의 플레이스에 구매자 앱을 거는 것은 별개 — 위 공개 소개·홈 화면 설치 결정)
- **PG(11/14, 11/15 순서 수정)**: 크몽·숨고는 플랫폼이 결제, 구매자 앱 결제는 구매자 명의 PG. 판매자 PG는 시스템 서비스 월 구독을 실제로 받거나 사이트에서 카드 결제를 받을 때 → 순서: 사업자 등록 → **포트원 전자결제 신청(PG 계약 → 구매안전서비스 이용확인증)** → 통신판매업 신고·변경신고(확인증 첨부) → 사이트에 사업자 정보·약관·환불 정책 → 심사 → 실결제(약 3주). 통신판매업 신고에 PG 확인증이 필요해서 PG가 신고보다 먼저. 카드 결제는 월 구독·개설비 같은 작은 금액에만(평균 100만 원 이상 고액은 PG 위험 업종), 납품형 고액은 계좌·세금계산서 또는 크몽·숨고 결제.
- **시스템 서비스 분리(11/14)**: 사이트를 앱 판매(납품형)와 시스템 서비스(자영업용, 월 구독 중심)로 나눔.
- **아이디어 사업자 고객층(11/14)**: "팔 것이 있고 사용자끼리 이어져야 하는데 개발이 필요한 사업자"(한일 매칭, K팝 굿즈 팬 마켓, 산책 메이트, 언어 교환, 클래스 마켓 등)를 앱 판매의 주 고객으로. 데이팅에 한정하지 않음. 업종별 신고·등록(결혼중개업법, 일본 인터넷이성소개사업 신고, 통신판매중개, 굿즈 초상권·상표)은 단정하지 않고 확인할 곳 안내.
- **분야별 전문 기능(11/14)**: 사용자 관리만이 아니라 분야 기능(학습 워크스페이스·학습 데이터 등)이 필요한 사업자용으로 기능 묶음을 보여 줌. 없는 것은 ○ 준비 중으로 정직하게 표시하고, 문의가 오면 공용 코어 모듈로 만들어 다음 구매자에게 재사용.
