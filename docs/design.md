# 페이지·스크린샷 디자인 기준

> 사이트(`index.html`)와 업종 소개 페이지(`demo/*.html`)를 만들거나 고칠 때, 장면 스크린샷을 찍거나 고를 때 따르는 기준이에요.
> 정한 날: 2026-11-16. 바꾸면 `docs/main.md` 8번 결정 기록에도 남겨 주세요.

## 왜 필요한가
모든 기능과 정보를 한 화면에 넣으면 전부 같은 무게로 보여서 방문자가 아무것도 기억하지 못해요.
예: 예전 `/demo/academy` 첫 화면은 같은 기능 셋(진단·시험지·앱 풀이)이 제목, 설명, 번호 목록에서 세 번 반복됐고, 버튼 두 개의 무게가 같았고, 스크린샷은 앱 전체를 찍어서 글자가 읽히지 않았어요.

## 1. 정보 위계: 한 층에 메시지 하나
- **섹션 하나 = 메시지 하나 = 기능 하나.** 섹션의 메시지를 한 문장으로 적을 수 없으면 섹션을 나눈다.
- **같은 기능은 페이지에서 한 번만 설명한다.** 제목·설명·목록·캡션에서 반복하지 않는다.
- 섹션마다 **가장 강한 요소는 하나**(제목 또는 스크린샷). 나머지는 확실히 작고 흐리게.
- 위에서 아래로 층을 내려가듯: 첫 화면 → 핵심 흐름 → 다음 단계·부가 기능 → 문의.

## 2. 첫 화면(히어로) 예산
| 넣는 것 | 개수 |
|---|---|
| 헤드라인: 고객이 얻는 **결과**를 약속(기능 나열 금지) | 1 |
| 보조 문장 | 1 (두 줄 이내) |
| 주 버튼(문의) | 1. 보조 동작은 글자 링크 수준으로 |
| 스크린샷: 첫 화면(약 900px 높이) 안에 크게 보이게 | 1 묶음 |
- 기능 번호 목록(1·2·3)은 첫 화면에 넣지 않는다. 그건 바로 아래 핵심 흐름 섹션의 일이다.
- 분류 표시(예: "학원 · 공부방 · 교습소")는 꼭 필요할 때만, 작게.

## 3. 핵심 흐름: 스크롤로 하나씩
- 추천 모듈은 순서대로 한 섹션씩 보여 준다(학원: 채점 → 진단 리포트 → 맞춤 시험지 → 앱에서 풀기 → 다시 진단).
- 섹션 구성: **제목 1줄 + 설명 2줄 이하 + 스크린샷 1장**(필요하면 장면 3~4컷을 넘겨 보기로).
- 스크롤할 때 스크린샷이 고정되고 장면만 바뀌는 방식(sticky)을 써도 좋다.
- 부가 기능(이름·색·로고, 설치 없이 입장 코드, 학부모 링크 등)은 핵심 흐름이 끝난 뒤 작은 카드 묶음으로.

## 4. 장면 스크린샷 규칙
- **스크린샷 1장 = 기능 1개.** 그 기능과 관계없는 영역은 넣지 않는다.
- **앱 전체 화면을 그대로 찍지 않는다.** 핵심 영역만 잘라서 크게 보여 준다. 캡처 스크립트는 페이지 전체가 아니라 **해당 요소만 캡처**(요소 스크린샷 또는 잘라낼 영역 지정)한다.
- 상단 탭·사이드 메뉴·설정 버튼 같은 **앱 공통 UI는 숨긴다**(필요하면 캡처용 표시 옵션으로).
- 가상 데이터는 최소한으로: 목록 3~4줄, 숫자는 한눈에 이해되는 값.
- **페이지에 실제로 표시되는 크기에서 본문 글자가 읽혀야 한다.** 안 읽히면 더 잘라낸다.
- 강조는 한 군데만(테두리·화살표·짧은 라벨 1개). 나머지는 흐리게 해도 된다.
- 설명 글은 스크린샷 안이 아니라 섹션 제목·캡션에 쓴다. 캡션은 한 줄.
- 기존 원칙 유지: 실제 앱 + 가상 데이터, 없는 기능은 화면 없이 "준비 중" + 흐름 3줄(가짜 화면 금지).
- **기능 소개 이미지는 범용 샘플로**(11/25): 사이트 첫 화면, 모듈 카드·상품 상세처럼 **기능 하나를 소개하는 자리**에는 운영 중인 앱 캡처를 그대로 쓰지 않는다. 같은 실제 앱으로 찍되 가상 데이터를 업종이 드러나지 않게 다시 넣는다.
  - 예: 끼니별 단백질(g) 그래프 → "주간 방문 수"·"월별 신청 수"처럼 어느 업종에나 맞는 값. 클라이밍장 신발 대여 대화 → 일반 모임 공지·일정 조율 대화. 영어 교정 예문도 특정 업종 단어(gym 등) 없이.
  - 한 페이지의 기능 소개 이미지들이 같은 업종으로 읽히지 않게 한다(같은 업종 데이터 2장 이상 금지).
  - 업종 페이지(`demo/<업종>.html`, `academy.html`)는 예외: 그 업종 데이터를 그대로 쓴다.

## 5. 검사
페이지나 스크린샷을 고친 뒤에는 `design-reviewer` 에이전트(`.claude/agents/design-reviewer.md`)로 검사하고, "수정 필요" 항목을 고친 뒤 완료한다. 에이전트를 쓸 수 없는 환경이면 같은 체크리스트로 직접 검사하고 결과를 PR 설명에 적는다.
